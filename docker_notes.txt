# 1. Introduction to Docker

### Definition

Docker is an open-source platform that enables developers to build, package, distribute, and run applications inside isolated environments called containers.

### Simple Explanation

Docker is a platform that packages an application along with its dependencies into a container.

### Example

Suppose you have developed a Machine Learning project using Python.

Your project requires:

* Python 3.10
* NumPy
* Pandas
* Scikit-learn
* TensorFlow

Now, when you try to run your project on another computer, you may face dependency-related issues.

Docker helps solve this problem.

### Real-Life Example

Suppose your application runs successfully on your laptop.

However, when you deploy it to an AWS server, you start getting errors.

Possible reasons:

* Python version mismatch.
* Library version mismatch.
* Missing dependencies.

Docker packages the application's environment, helping maintain consistency across different deployment environments.

### Important Terms

* **Docker:** A containerization platform.
* **Container:** An isolated application environment.
* **Image:** A template used to create containers.
* **Dockerfile:** An instruction file used to build Docker images.
* **Docker Engine:** The core technology responsible for running Docker containers.

# 2. Problems Before Docker

Before Docker, developers faced several challenges while developing and deploying applications.

### Common Problems

**1. Dependency Issues**

Different systems may have different versions of libraries and dependencies.

**2. Environment Mismatch**

The development environment on a developer's laptop may differ from the production server environment.

**3. Deployment Problems**

Applications often required manual configuration before deployment.

**4. Resource Consumption**

Traditional Virtual Machines generally require more system resources.

**5. Portability**

Running applications consistently across different environments could be difficult.

### Solution

Docker containerizes applications along with their dependencies and configurations, making deployment more consistent and manageable.

# 3. What is Containerization?

### Definition

Containerization is a technology that packages an application along with its dependencies into an isolated, portable, and lightweight unit called a container.

### Explanation

Containerization means running an application inside an isolated environment.

### Example

Suppose your laptop has three applications:

1. Python ML Application
2. Node.js Application
3. MySQL Database

All these applications may require different dependencies.

Docker allows you to run each application inside a separate container.

This helps reduce dependency conflicts.

### Benefits

* Portability
* Isolation
* Faster deployment
* Resource efficiency
* Scalability

# 4. Docker Architecture

Docker follows a Client-Server Architecture.

The main components of Docker architecture are:

1. Docker Client
2. Docker Daemon
3. Docker Host
4. Docker Registry

### Architecture Flow

```text
       Docker Client
             |
             |
          REST API
             |
             v
       Docker Daemon
             |
       +-----+------+
       |            |
       v            v
    Images      Containers
       |
       |
       v
  Docker Registry
```

### 1. Docker Client

**Definition:** Docker Client is the interface through which users interact with Docker.

Example:

```bash
docker run nginx
```

When you execute this command, the Docker Client sends a request to the Docker Daemon.

### 2. Docker Daemon

**Definition:** Docker Daemon is a background service responsible for managing Docker objects.

Its responsibilities include:

* Managing images.
* Creating containers.
* Managing networks.
* Managing volumes.

Docker Daemon is commonly known as `dockerd`.

### 3. Docker Host

Docker Host is the machine where Docker Engine and containers run.

Examples:

* Your Laptop
* AWS EC2 Server
* Linux Server

### 4. Docker Registry

**Definition:** Docker Registry is a storage system used to store and distribute Docker images.

Example: Docker Hub.

# 5. Docker Components

The important components of Docker are:

### A. Docker Engine

Docker Engine is the core technology responsible for building and running Docker containers.

### B. Docker Image

**Definition:** A Docker Image is a read-only template used to create Docker containers.

**Simple Explanation:**

An image works like a blueprint.

Example:

```bash
docker pull python:3.10
```

This command downloads the Python 3.10 image.

### C. Docker Container

**Definition:** A Docker Container is a runnable instance of a Docker image.

**Simple Explanation:**

A container is created from an image.

Example:

```bash
docker run python:3.10
```

### D. Dockerfile

**Definition:** A Dockerfile is a text file containing instructions to build a Docker image.

Example:

```dockerfile
FROM python:3.10
WORKDIR /app
COPY . .
CMD ["python", "app.py"]
```

### E. Docker Compose

Docker Compose is a tool used to define and manage multiple containers together.

Example:

An application may contain:

* Frontend
* Backend
* Database

Docker Compose allows you to manage all three services together.

# 6. Docker vs Virtual Machine

Both technologies provide virtualization and isolation, but they use different approaches.

| Feature          | Docker Container        | Virtual Machine               |
| ---------------- | ----------------------- | ----------------------------- |
| Architecture     | Containerization        | Hardware virtualization       |
| Operating System | Shares the host kernel  | Has its own guest OS          |
| Size             | Generally smaller       | Generally larger              |
| Startup          | Fast                    | Comparatively slow            |
| Resource Usage   | Generally lower         | Generally higher              |
| Isolation        | Process-level isolation | Hardware-level virtualization |
| Performance      | Lower overhead          | More overhead                 |

### Virtual Machine Architecture

```text
        Applications
        Libraries
        Guest OS
        Hypervisor
        Hardware
```

### Docker Architecture

```text
        Applications
        Libraries
        Docker Container
        Docker Engine
        Host OS
        Hardware
```

**Interview Point:**

Containers share the host operating system kernel, whereas virtual machines run their own guest operating systems.

A Docker Image is a lightweight, standalone, executable package that contains everything required to run an application.

### What Does a Docker Image Contain?

* Application Code
* Runtime
* Libraries
* Dependencies
* Configuration

### Important Image Commands

**1. Download an Image**

```bash

```

**2. List Images**

```bash

```

**3. Build an Image**

```bash
docker build -t myapp .
```

**4. Remove an Image**

```bash
docker rmi myapp
```

**5. Inspect an Image**

```bash
docker inspect myapp
```

**6. View Image History**

```bash
docker history myapp
```

### Image Layers

Docker images consist of multiple layers.

Example:

```text
        Application Code
        ----------------
        Dependencies
        ----------------
        Python Runtime
        ----------------
        Base Image
```

Each Dockerfile instruction can create a new image layer.

Docker uses layer caching to make repeated builds faster.

# 10. Dockerfile

Dockerfile is one of the most important concepts in Docker.

### Definition

A Dockerfile is a text document that contains instructions used to build a Docker image.

### Example: Python Application

Project Structure:

```text
my-project/
│
├── app.py
├── requirements.txt
└── Dockerfile
```

### app.py

```python
print("Hello from Docker!")
```

### requirements.txt

```text
numpy
pandas
```

### Dockerfile

```dockerfile
FROM python:3.10

WORKDIR /app

COPY requirements.txt .

RUN pip install -r requirements.txt

COPY . .

CMD ["python", "app.py"]
```

### Dockerfile Instructions

| Instruction | Meaning                                               |
| ----------- | ----------------------------------------------------- |
| FROM        | Defines the base image                                |
| WORKDIR     | Sets the working directory                            |
| COPY        | Copies files into the image                           |
| ADD         | Copies files and can extract archives                 |
| RUN         | Executes commands during image building               |
| CMD         | Defines the default startup command                   |
| ENTRYPOINT  | Defines the main executable                           |
| ENV         | Sets environment variables                            |
| EXPOSE      | Documents the intended container port                 |
| ARG         | Defines a build-time variable                         |
| USER        | Sets the user for subsequent instructions and runtime |
| VOLUME      | Declares a mount point                                |

### RUN vs CMD

| RUN                            | CMD                                                 |
| ------------------------------ | --------------------------------------------------- |
| Executes during image building | Defines the default command when a container starts |
| Creates an image layer         | Defines the default startup behavior                |

### CMD vs ENTRYPOINT

`CMD` defines the default command or arguments.

`ENTRYPOINT` defines the primary executable of a container.

Both can be used together.

Example:

```dockerfile
ENTRYPOINT ["python"]
CMD ["app.py"]
```

# 12. Docker Volumes

### Definition

Docker Volumes are used to persist data generated and used by Docker containers.

### Problem

Normally, when a container is removed, its writable filesystem data is also removed.

### Example

Suppose you have a MySQL container.

Your database data is stored inside it.

If you remove the container without persistent storage, you may lose the database data.

### Solution: Volumes

Volumes store data independently of a container's lifecycle.

### Volume Commands

**Create a Volume**

```bash
docker volume create mydata
```

**List Volumes**

```bash
docker volume ls
```

**Inspect a Volume**

```bash
docker volume inspect mydata
```

**Remove a Volume**

```bash
docker volume rm mydata
```

### Attach a Volume

```bash
docker run -d \
  --name mycontainer \
  -v mydata:/app/data \
  nginx
```

Here:

* `mydata` = Volume name.
* `/app/data` = Mount location inside the container.

### Types of Storage

| Type       | Purpose                                           |
| ---------- | ------------------------------------------------- |
| Volume     | Persistent Docker-managed storage                 |
| Bind Mount | Mounts a specific directory from the host machine |
| tmpfs      | Memory-based temporary storage                    |

# 13. Docker Networking

### Definition

Docker Networking allows containers to communicate with each other and with external networks.

### Simple Explanation

Suppose you have:

* Frontend Container
* Backend Container
* Database Container

Networking allows these containers to communicate with each other.

### Docker Network Types

**1. Bridge Network**

A common networking mode for containers running on a single Docker host.

**2. Host Network**

The container shares the host's networking namespace. This is mainly relevant on Linux.

**3. None Network**

The container does not receive normal external network connectivity.

**4. Overlay Network**

Provides networking across multiple Docker hosts, commonly used with Docker Swarm.

### Network Commands

```bash
docker network ls
docker network create mynetwork
docker network inspect mynetwork
docker network rm mynetwork
```

Connect a container to a network:

```bash
docker network connect mynetwork mycontainer
```

# 14. Docker Compose

### Definition

Docker Compose is a tool used to define and manage multi-container Docker applications using a YAML configuration file.

### Example

Suppose you are developing an AI chatbot.

Your project contains:

1. FastAPI Backend
2. PostgreSQL Database
3. Redis Cache

Managing all these containers separately can become difficult.

Docker Compose allows you to define and manage these services together.

### docker-compose.yml

```yaml
services:

  backend:
    build: .
    ports:
      - "8000:8000"
    depends_on:
      - database

  database:
    image: postgres:16
    environment:
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: password
      POSTGRES_DB: mydb
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

### Important Commands

**Start Services**

```bash
docker compose up
```

**Run in the Background**

```bash
docker compose up -d
```

**Stop Services**

```bash
docker compose down
```

**Build Services**

```bash
docker compose build
```

**View Containers**

```bash
docker compose ps
```

**View Logs**

```bash
docker compose logs
```

**Follow Logs**

```bash
docker compose logs -f
```

**Note:** `docker compose down -v` can also remove named volumes. This may delete persistent database data.

# 16. Docker Port Mapping

### Definition

Port Mapping allows external traffic to access a service running inside a Docker container.

### Example

```bash
docker run -d -p 8000:8000 myapp
```

This means:

```text
Host Port : Container Port
    8000   :      8000
```

If you open the following address in your browser:

```text
http://localhost:8000
```

The request can reach the application running inside the container.

### Important: EXPOSE vs -p

* **EXPOSE:** Documents the intended port in a Dockerfile.
* **-p:** Creates an actual host-to-container port mapping.

# 19. Docker Multi-stage Builds

### Definition

Multi-stage builds allow developers to use multiple FROM instructions in a Dockerfile to create smaller and more efficient final images.

### Problem

During the build process, several unnecessary dependencies and tools may be installed.

However, the production application may not need all of them.

Multi-stage builds help exclude unnecessary build tools from the final image.

### Example

```dockerfile
FROM python:3.10 AS builder

WORKDIR /app

COPY requirements.txt .

RUN pip install --prefix=/install -r requirements.txt


FROM python:3.10-slim

WORKDIR /app

COPY --from=builder /install /usr/local

COPY . .

CMD ["python", "app.py"]
```

### Explanation

* The first stage installs dependencies.
* The second stage prepares the final runtime image.
* Unnecessary build tools from the first stage are not included in the final image.

# 20. Docker Security

Docker security is important, especially when deploying production applications.

### Important Security Practices

1. Use trusted base images.
2. Avoid running containers as the root user.
3. Never hardcode API keys.
4. Update images regularly.
5. Avoid installing unnecessary packages.
6. Give containers only the permissions they require.
7. Scan images for vulnerabilities.

### Non-root User Example

```dockerfile
FROM python:3.10-slim

WORKDIR /app

RUN useradd -m appuser

COPY . .

USER appuser

CMD ["python", "app.py"]
```

# 25. Docker vs Kubernetes

These are two different technologies.

| Docker                                              | Kubernetes                                     |
| --------------------------------------------------- | ---------------------------------------------- |
| Container platform                                  | Container orchestration platform               |
| Builds and runs containers                          | Manages containers                             |
| Useful for individual hosts                         | Can scale across multiple machines             |
| Docker Compose manages multi-container applications | Kubernetes manages large distributed workloads |
| Manages container lifecycle                         | Manages scheduling, scaling, and recovery      |

### Simple Example

**Docker:**

Creating and running a container.

**Kubernetes:**

Managing hundreds of containers across multiple servers.

**Note:** Kubernetes does not require Docker Engine specifically. It supports multiple container runtimes.
